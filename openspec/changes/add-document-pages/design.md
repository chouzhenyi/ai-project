## Context

项目已有 EasyTable 和 EasyForm 两个配置化组件，分别支持表格展示/编辑和表单渲染。现有路由使用 react-router-dom v6 的 `createBrowserRouter`，所有视图 lazy-loaded，侧边栏使用 Ant Design Menu。

## Goals / Non-Goals

**Goals:**

- 在 `src/views/document/` 下新建单据列表页和新建/编辑页
- 单据列表使用 EasyTable 配置化表格，支持搜索、分页、操作列
- 单据表单页面顶部为操作栏模块，下方 7 个信息模块从上到下依次排列，基本信息模块使用 EasyForm 表单直接录入，其余模块使用 EasyTable 表格 + Drawer 抽屉模式
- 通过路由参数 `:id` 区分新建/编辑模式
- 注册路由并集成侧边栏菜单

**Non-Goals:**

- 后端 API 实现（使用模拟数据）
- 附件真实上传功能（使用 Upload 组件展示 UI，实际上传逻辑由后续迭代完成）
- 权限控制
- 单据审批流程

## Decisions

### 目录结构

新页面放在 `src/views/document/` 目录下：

- `index.tsx` — 单据列表页（默认导出，用于 lazy import）
- `Form.tsx` — 单据新建/编辑页（默认导出，用于 lazy import）

理由：与现有 `src/views/` 下的扁平结构保持一致，每个功能模块独立目录。

### 新建/编辑页使用同一组件

通过 `useParams` 获取 `:id` 参数判断模式：有 `id` 为编辑模式，无 `id` 为新建模式。编辑模式时通过 `id` 加载已有数据填充表单。

理由：新建和编辑的界面和字段完全一致，共用组件避免重复代码。

### 页面顶部操作栏

页面顶部固定一个操作栏模块，包含以下按钮：保存、提交审批、创建报账单、创建付款单、废弃。操作栏位于所有信息模块之上。

- **保存**：保存当前单据数据（新建追加、编辑更新），不改变单据状态
- **提交审批**：保存并将单据状态改为"已提交审批"
- **创建报账单**：基于当前单据生成一条关联报账单（当前为 Demo，仅弹出提示）
- **创建付款单**：基于当前单据生成一条关联付款单（当前为 Demo，仅弹出提示）
- **废弃**：将单据状态改为"已废弃"，需确认弹窗

理由：企业单据页面通常需要在顶部提供全局操作入口，方便用户快速执行业务操作。保存与提交审批分开，允许用户暂存草稿后再提交；创建报账单/付款单属于下游业务关联，废弃为终止流程操作。

### 页面布局：垂直依次排列

单据包含 7 个信息模块，从上到下依次排列，每个模块用 Ant Design `Card` 或带标题的区域分隔。**基本信息** 模块直接使用 EasyForm 实例渲染字段。其余 6 个模块（发票信息、配件信息、设备信息、供应商信息、附件信息、关联单据信息）采用 **表格 + 抽屉** 模式：

- 模块内使用 EasyTable 展示该模块的列表数据，右侧操作列提供"编辑"、"删除"按钮
- 表格顶部放置 buttonGroup，提供"新建"入口
- 点击"新建"或"编辑"时打开同一 Drawer 抽屉，抽屉内使用 EasyForm 表单录入数据
- 抽屉提交后，数据回写到对应模块的表格中（新建追加行，编辑更新行）

理由：7 个模块从上到下依次排列，用户无需切换 Tab 即可一览全貌，向下滚动即可逐个查看和填写。发票、配件、设备、供应商、附件、关联单据等模块天然具有多条记录的特征，使用表格展示比单表单更直观；配合 Drawer 抽屉的新建/编辑交互，既保持数据列表的可浏览性，又避免页面过于拥挤。基本信息模块仅一条记录，直接使用 EasyForm 即可。

### 数据模型

所有单据字段扁平化存储在一个 data 对象中（配合 EasyForm），用一个顶层 `Record<string, unknown>` 表示。表单提交和列表展示均使用同一数据结构。

理由：EasyForm 和 EasyTable 均基于扁平 key-value 设计，无需嵌套数据结构。

### 模拟数据层

使用 `useState` 管理内存中的单据列表数据，`useCallback` 封装 CRUD 操作。列表页和表单页通过路由参数传递数据（编辑时传递 id，表单页从共享数据中查找）。

为避免跨页面数据共享的复杂性，在列表页维护一个 `documents` 状态数组，表单页通过 URL 参数获取 id 后从同一数据源读取。实际项目中这个状态会由状态管理库或 API 调用替代。

## Risks / Trade-offs

| Risk                                                               | Mitigation                                                                 |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 模块过多导致页面过长，需要大量滚动                                 | 每个模块使用 Card 组件清晰分隔，配合 Anchor 锚点导航可快速定位             |
| 内存模拟数据在页面刷新后丢失                                       | 明确标注为 demo 数据，实际接入 API 后持久化                                |
| 编辑模式数据同步问题（用户在表单页修改后返回列表，列表可能未更新） | 表单提交时将更新数据通过回调传给列表页，或使用 `window.history.state` 传递 |

## Open Questions

- 配件信息模块中的子表格是否需要支持行内编辑（EasyTable 的 `editable` 模式）？当前设计使用表格 + Drawer 模式
- 关联单据的添加方式：从已有单据中选择还是手动输入？当前设计为手动输入表格
- 是否需要页面右侧 Anchor 锚点导航，方便快速跳转到各模块？
